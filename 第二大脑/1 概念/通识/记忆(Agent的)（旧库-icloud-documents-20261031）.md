#  💡Summary  

> [!Info]
> 一句话说清楚
> 

记忆的本质其实是两个，一个是记，代表着写数据，一个是忆，代表的是检索数据。
1. 作为一个 Agent 来说，记这个动作其实相对还好，因为所有的东西本来就是数字化的，核心在于忆。
2. 然后忆这个事的话，我觉得其实是可以被系统性设计的，就是说要去，就它其实是个效率，类似于一个缓存的逻辑嘛，因为你一直 grab 的话，始终还是能找到的。但是呢，在某一个业务域下，这个忆优先去缓存的一些信息，就是体现了业务主张。然后我觉得这个东西是可以被评测，或者说是离线的 Agent 不断去发现出来的。比如说用户的哪些 query 其实是和之前的 history 有关联的，用哪个信息的话可以辅助 query 的解决。然后通过这个方式慢慢的去发现出来那些有用的、值得被特殊缓存的信息。

4. 新增数据
	1. 构建四路索引
	2. 归纳：后台将多条事实归纳成持续更新的 observations。例如，从多次交流归纳出“用户以前偏爱 React，现在转向 Vue”。
