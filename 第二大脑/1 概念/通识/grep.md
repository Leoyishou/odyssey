# 🪞Notes


grep 的搜索对象确实是**行**，但它的本质**不是 BM25**，而是**模式匹配**：只判断一行“匹配 / 不匹配”，不打分、不排序。

**grep 和 BM25 的区别**

||grep|BM25|
|---|---|---|
|判断方式|这一行能不能被正则匹配上，结果只有是或否|给每个文档算一个相关度分数|
|有没有排序|没有，按文件顺序、行顺序输出|按分数从高到低排|
|搜索单位|**行**|文档或 chunk|
|要不要预先建索引|不要，每次现场把文件从头扫一遍|要，先建倒排索引|
|查询怎么理解|整个模式作为一个正则来匹配|拆成多个词，每个词分别计分|
|词频、稀有度|不考虑|核心就是它：词出现越多分越高，越稀有的词权重越大，文档越长分越低|

**一个例子**

搜 `error timeout`：

- **grep**：只返回**字面包含** **`error timeout`** **这串连续字符**的行。只有 `error` 或只有 `timeout` 的行都不会命中，`timeout ... error` 这种顺序反过来的也不会。
- **BM25**：把查询拆成 `error` 和 `timeout` 两个词，包含其中任意一个的文档都可能被召回。两个都有、出现次数多、或者用词更稀有的文档排得更前。

grep 本身不会帮你改写查询。改写全不全，完全取决于模型懂多少、有多耐心。

## 一、为什么只靠一个词会漏

“核心看板”在不同项目里可能被写成：

|类型|可能的写法|
|---|---|
|中文同义词|核心看板、主看板、数据看板、仪表盘、驾驶舱、大屏、概览|
|英文|dashboard、board、overview、cockpit、kpi、metrics、home|
|命名风格|`CoreDashboard`、`core_dashboard`、`core-dashboard`、`coreBoard`|
|缩写|`dash`、`cdb`、`kpiBoard`|
|内部代号|“北极星”、`polaris`，这类**没法猜**|

只用 grep 搜“核心看板”这四个字，只能命中字面写着这四个字的地方，比如注释、多语言文案、文档。

## 二、好的 agent 会怎么改写和搜索

**1. 一次搜多个写法（用正则把同义词并在一起）**

```
grep -rniE "核心看板|主看板|仪表盘|驾驶舱|dashboard|cockpit|kpi" .
```

`-i` 忽略大小写，所以 `CoreDashboard`、`core_dashboard`、`core-dashboard` 都能被 `dashboard` 命中。命名风格的问题基本靠这个解决。

**2. 先搜“入口”，再顺藤摸瓜**

中文名常出现在多语言文案、菜单或路由配置里：

```
第 1 步：grep "核心看板"
  → 在 locales/zh.json 里命中："menu.coreBoard": "核心看板"
第 2 步：grep "coreBoard"
  → 在 router.ts 里命中：{ path: '/core', component: CoreBoardPage }
第 3 步：grep "CoreBoardPage"
  → 找到组件文件
```

这一步很关键。**每次搜到的结果，都会给下一次搜索提供新的关键词。** 这和前面说的图检索思路一样：从一个实体出发，沿着引用关系一跳一跳走下去。区别在于这里由 LLM 手动来走。

**3. 从结构入手（如果有** **`find`** **或** **`ls`****）**

先看目录结构，比如 `pages/`、`views/`、`dashboard/`，经常比搜内容更快。

## 三、会漏在哪

|情况|原因|
|---|---|
|内部代号或黑话|模型不知道“北极星”就是核心看板|
|只有语义描述、没有关键词|比如注释写的是“老板每天早上看的那个页面”|
|名字是拼出来的|比如 `` `${type}Board` ``，grep 搜不到完整的字符串|
|不在文本文件里|图片、二进制文件、数据库配置、远程接口返回的内容|
|太宽泛|`board` 命中上千行，超过 100 条的上限被截断，真正的结果可能被挤掉|
|模型太早停下|第一个词命中一点东西，就以为找到了|

## 四、怎么提高命中率

1. **在 prompt 里要求多轮搜索**：至少同时试中文、英文、缩写三类写法，并且要沿着命中结果继续追。
2. **给项目加“术语表”**：在 `AGENTS.md` 或 README 里写清楚“核心看板 = `CoreBoard`，路由 `/core`”。只要 grep 能搜到这一行，后面就顺了。
3. **配合** **`find`** **和** **`ls`**：用文件名和目录结构做补充。
4. **需要语义召回时加向量检索**：用户的说法和代码里的叫法差得太远时，grep 补不上，这正是稠密检索的长处。
