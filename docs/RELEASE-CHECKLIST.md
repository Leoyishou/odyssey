# 版本回归流程

每次大版本及影响编辑/存储的迭代执行；上次通过不直接算作本次通过。

- 记录上游基线、源码提交或差异快照、构建号、设备与二进制 SHA-256。
- 执行 `scripts/check.sh`，保留测试、指南往返和 clippy 日志。编辑内核变化补充 `FDL_FUZZ_SEEDS=2000 cargo test --release random_edits`。
- 使用独立测试库和 `tools/harness` 检查输入/中文组合、选择、粘贴、撤销重做、存盘与重启。
- 表格回归：单元格建链、别名、预览、跳转、反链回格、重命名、行列/合并操作后保存重启。
- 工作区回归：原动作入口映射、左右栏折叠调宽、大纲与反链跳转、焦点、设置弹窗；浅深主题保持 quiet.md 风格。
- Vault 回归：新建/取消/拒绝覆盖、开库前保存、两个相同文档 ID 的库隔离、最近库与重启、缺失路径、移除不删除、非法格式零写入。脚本的 `vault-launch.json` 只是请求收据，真实启动参数和跨进程保存须另测。
- 旧库恢复回归：纯 XML 默认库继续发现并原位打开；混合库提示及只读复制原生文档；12 份 XML/UUID/索引/附件/设置保留；仅原生模式不读 Markdown；复制后移动源库仍可解析绝对附件/封面；含 format.json/.obsidian 的只读源目录文件集合和 SHA 不变。原生恢复与 Markdown 转换分别记数量和限制。
- 系统 GUI 验证只操作隔离应用/测试库；屏外截图不能代替系统输入法、原生文件选择器和材质验证。不执行锁屏、解锁或退出用户应用。
- 对照 [ACCEPTANCE.md](ACCEPTANCE.md) 逐项记录本次通过、部分通过、失败或未测及证据；仅整项通过才勾选。测试数据、日志和真实用户库不进入公开源码。
- 对打包产物重新检查 Bundle ID、构建号、签名、安装与隔离启动；本地 ad-hoc 包不可标为已公证公开发行。
- 更新 README 和版本记录，如实列出未实现项。MIT 和第三方版权保留。发布目的仓库与身份确认后再推送，禁止推向上游或个人笔记库。
