## 一、对应[[SQL]]的筛选、分组、排序

按**日常数据分析 / 取数 SQL**的使用频率粗排，非严格统计：

|   多维表格中的概念 | SQL 语法                                  | 用途         | 示例                                                         |
| ---------: | --------------------------------------- | ---------- | ---------------------------------------------------------- |
|     **字段** | `SELECT`                                | 选择字段       | `SELECT user_id, amount`                                   |
|    **数据表** | `FROM`                                  | 指定数据表      | `FROM orders`                                              |
|     **筛选** | `WHERE`                                 | 行级过滤       | `WHERE dt = '2026-06-01'`                                  |
|            | `AND` / `OR` / `NOT`                    | 组合条件       | `WHERE a = 1 AND b > 0`                                    |
|     **分组** | `GROUP BY`                              | 分组统计       | `GROUP BY city`                                            |
|            | `COUNT` / `SUM` / `AVG` / `MAX` / `MIN` | 聚合计算       | `COUNT(*)`, `SUM(amount)`                                  |
|     **排序** | `ORDER BY`                              | 排序         | `ORDER BY cnt DESC`                                        |
|            | `LIMIT`                                 | 限制返回条数     | `LIMIT 100`                                                |
| **查找引用字段** | `JOIN ... ON`                           | 多表关联       | `JOIN users u ON o.user_id = u.id`                         |
|            | `LEFT JOIN`                             | 保留左表关联     | `LEFT JOIN dim_city c ON ...`                              |
|            |                                         |            |                                                            |
|            | `CASE WHEN`                             | 条件分桶 / 打标签 | `CASE WHEN amount > 100 THEN '高' ELSE '低' END`             |
|            | `DISTINCT`                              | 去重         | `SELECT DISTINCT user_id`                                  |
|            | `HAVING`                                | 聚合后过滤      | `HAVING COUNT(*) > 10`                                     |
|            | `WITH`                                  | CTE 临时结果   | `WITH t AS (...) SELECT * FROM t`                          |
|            | `IN`                                    | 多值匹配       | `WHERE city IN ('北京','上海')`                                |
|            | `BETWEEN`                               | 区间过滤       | `WHERE amount BETWEEN 10 AND 100`                          |
|            | `LIKE`                                  | 模糊匹配       | `WHERE name LIKE '%餐饮%'`                                   |
|            | `IS NULL` / `COALESCE`                  | 空值判断和兜底    | `COALESCE(phone, '未知')`                                    |
|            | 窗口函数 `OVER`                             | 排名、去重、累计   | `ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY ts DESC)` |
|            | `UNION ALL`                             | 合并多段结果     | `SELECT ... UNION ALL SELECT ...`                          |
|            |                                         |            |                                                            |

如果是做业务分析，最应该先熟练的是：`SELECT / FROM / WHERE / GROUP BY / 聚合函数 / JOIN / CASE WHEN / WITH / 窗口函数`。这几个基本覆盖 80% 以上的取数场景。

### JOIN

| 概念     | 你的理解          | 更准确的说法                            |
| ------ | ------------- | --------------------------------- |
| 双向关联字段 | 行维度的选择联表，偏静态  | 对，核心是**手动/半手动建立两条记录之间的关系**        |
| 查找引用字段 | 动态 JOIN 出来的结果 | 对，核心是**基于已有关系或条件，把另一张表的字段值动态带出来** |

### 低代码
